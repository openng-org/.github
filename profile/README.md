# OpenNG

**Keeping Angular open source sustainable.**

[OpenNG](https://www.openng.org/) is a community hub focused on maintenance — the work that keeps libraries alive after the initial excitement fades. This GitHub organization is where we host, maintain, and collaborate on the Angular open-source projects we steward.

When maintainers step away, critical tooling should not disappear with them. OpenNG steps in where maintenance has stalled and the community still depends on a project.

## What we do

### Revive abandoned projects

We bring neglected libraries back to a healthy, maintained state: triaging issues, cutting releases, updating dependencies, and restoring confidence for teams that rely on them.

### Connect projects with maintainers

Maintenance is often a lonely journey. We help match projects with contributors and maintainers who are willing to carry them forward, with clear onboarding and shared expectations.

### Support the wider Angular OSS ecosystem (upcoming)

Beyond our own repositories, we promote quality open source, help libraries find contributors, and work to raise the bar on maintenance standards across the Angular community.

## Why this GitHub organization exists

Each repository here is part of a deliberate effort to preserve software the community still needs. You will find maintained Angular libraries under OpenNG initiative, contribution guides and issue templates, security policies for responsible disclosure, and a place to collaborate on fixes, releases, and long-term project health.

## Where we are today

OpenNG is in an early stage and we are building in phases:

1. **Initiative and first cohort** — launch [openng.org](https://www.openng.org/), set up community channels, and maintain the first cohort of six libraries.
2. **Beyond the first cohort** — evaluate other abandoned Angular libraries the community still relies on.
3. **Ecosystem support** — identify practical ways to help the wider Angular open-source landscape (upcoming).
4. **Sponsorship** — find sponsors to fund maintenance work and governance costs (upcoming).

## Get involved

You do not need to be a core maintainer to help:

- **Use and star** the projects you depend on — visibility matters.
- **Report bugs** with clear reproduction steps using our issue templates.
- **Open pull requests** for fixes, docs, and tests — see [CONTRIBUTING.md](../CONTRIBUTING.md).
- **Review issues and PRs** in the libraries you care about.
- **Propose maintainers** for projects that need ongoing stewardship.

For security issues, follow our [security policy](../SECURITY.md) — do not open public issues for vulnerabilities.
